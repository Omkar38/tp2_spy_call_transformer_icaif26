\section*{Purpose}

This report documents the first implementation stage of the professor-proposed
TP2-MV-ALiBi transformer. The goal of this stage is not to train the transformer
yet. The goal is to produce the leakage-safe T1/K2 token dataset and the stable
feature dictionary \( \mathcal F^\star \) that the transformer will consume.

\section*{Implemented}

\begin{itemize}
  \item Created \texttt{TP2MVTransformer/01\_build\_feature\_dictionary.py}.
  \item Built one token row per \((\mathrm{episode}, \mathrm{strategy})\) for \(T1\) and \(K2\).
  \item Used corrected expiry-payoff labels only: \texttt{exit\_selected\_leg\_expiration\_payoff}.
  \item Excluded \texttt{signal\_year}, all \texttt{label\_*} columns, realized P\&L columns, future exit fields, and validity/result columns from candidate inputs.
  \item Trained rolling LightGBM models only for feature discovery.
  \item Saved a frozen feature dictionary for downstream transformer training.
\end{itemize}

\section*{Interpretation}

The selected dictionary is consistent with the professor's design. Many stable
features describe the short \(D\)-leg, liquidity, option-surface location, and
TP2 severity. That means the data-driven feature discovery is aligned with the
proposed multivariate ALiBi distances:

\[
D_{\mathrm{time}},\quad
D_{\mathrm{surface}},\quad
D_D,\quad
D_{\mathrm{liq}},\quad
D_{\mathrm{life}}.
\]

The lifecycle block selected fewer features than expected in this first pass.
This does not mean lifecycle is unimportant; it means the current LightGBM
feature-discovery pass ranked short-D-leg and liquidity variables more strongly.
Lifecycle features can still be included in the transformer distance vector as a
pre-specified structural block.
